## 一、项目概况

### 技术栈
- 后端：Flask + SQLite（database.py + app.py）
- 前端：Jinja2 模板 + 原生 JS + CSS
- 视觉风格：手绘植物志（Botanical Journal），暖色调纸张质感
- 字体：ZCOOL XiaoWei（标题）、Noto Serif SC（正文）、Courier New（数字）
- CSS 变量：`--bg`, `--bg2`, `--ink`, `--muted`, `--pencil`, `--accent`, `--accent-rose`, `--shadow`

### 当前页面结构
- 底部导航 4 个 tab：记录（首页）| 黑板 | 档案 | 设置
- 首页：状态条 + 签到表单 + 等级卡片 + 数据统计 + 每日一签
- 档案页 5 个子 tab：记录列表 | 日历 | 图鉴 | 标签筛选 | 成长
- 黑板页：搜索栏 + 便利贴墙 + 留言输入
- 设置页：备份/恢复、排序设置等

### Bv3 已完成的工作
1. 移除了对比功能（有 bug 且与成长时间线/GIF 功能重复）
2. 新增 4 个趣味功能：等级系统（XP/8级）、数据统计、植物日签（30条）、植物心情
3. 首页布局全面优化：紧凑头部 + 状态条（等级+最近记录内联）+ 签到表单提前 + 趣味卡片紧凑化 + 数据内联
4. 档案页紧凑化：header-compact + tabs 滚动
5. 黑板页输入区提升到搜索栏之后
6. CSS 全局统一规范（卡片风格统一为 sketch-card 双边框手绘风格）

### 数据库结构（database.py）
- `watering_logs`：签到记录（id, name, created_at, like_count, void）
- `photos`：照片（id, log_id, file_path, caption, created_at）
- `tags`：标签（id, name）
- `photo_tags`：照片-标签关联（photo_id, tag_id）
- `board_messages`：黑板留言（id, author, content, chalk_color, created_at）
- `photo_comments`：照片留言（id, photo_id, author, content, created_at）
- `likes`：点赞（id, log_id, author）
- `backups`：备份记录

### XP 计算公式
```
total_xp = log_count * 5 + photo_count * 15 + comment_count * 3 + like_count * 2 + board_count * 3
```

### 等级体系
种子(0) → 发芽(50) → 幼苗(150) → 成长(300) → 茂盛(500) → 开花(800) → 硕果(1200) → 园艺大师(1800)

## 二、产品调性与文案风格

### 核心定位
**"一本有灵魂的植物日记"** —— 视觉上是正经的手绘植物志，但交互和文案让人会心一笑。这种反差是产品的记忆点：看起来像个老学究的植物笔记，打开一看全是有趣的灵魂。

### 文案原则
**不搞笑，但要有趣。** 不是段子手风格，而是一个热爱植物的人在自言自语时的那种温暖和俏皮。

### 文案示例对照表

| 场景 | 基础文案 | 推荐风格 |
|------|---------|---------|
| 空状态（无记录） | "尚无记录" | "这片土壤还在等待第一颗种子" |
| 多天未记录 | "7天未记录" | "你的植物想你了，已经7天没去看它了" |
| 未解锁图鉴 | "未解锁" | "这株植物还在路上，等你去发现" |
| 计划迎接完成 | "已完成" | "欢迎新成员加入你的植物园" |
| 每日一签刷新 | "换一条" | "再听一个植物的秘密" |
| 签到成功 | "已记录" | "又一天的植物故事，已收录" |
| 首次解锁图鉴 | "已解锁" | "恭喜，你成功收录了一株新植物" |
| 图鉴收集进度 | "已解锁 12/50" | "你的植物园已有 12 位住客，还有 38 位在路上" |
| 待办完成 | "已完成" | "干得漂亮，你的植物感谢你" |
| 无留言 | "暂无留言" | "黑板还是空的，来留下第一笔吧" |
| 无搜索结果 | "无结果" | "没有找到匹配的留言，换个词试试" |
| 加载更多 | "加载更多" | "翻翻过去的日记..." |

### 注意事项
- **等级名称保持现有风格**：种子、发芽、幼苗、成长、茂盛、开花、硕果、园艺大师——这些偏正经，不需要改
- **页面标题保持简洁**：如"植物日志"、"观察档案"等主标题不需要俏皮化，俏皮感体现在副标题、空状态、提示语等辅助文案中
- **不要过度**：不是每句话都要有趣，正常的功能性文案（按钮、标签名、表单提示）保持清晰直接即可

## 三、待实现修改点（按讨论顺序）

### 修改点 1：签到表单加「影像/文字」模式切换

**背景**：用户认为拍照签到和黑板留言本质上都是"记录观察"，影像占 60% 重要性，文字占 40%。

**具体方案**：
- 签到表单顶部加两个小 tab：「影像」|「文字」
- 默认「影像」——就是现在的拍照签到流程，不变
- 切到「文字」——表单变成：名字输入 + 文本输入框 + 发布按钮，数据走 `/api/board` 接口
- 两个模式共用一个提交区域，视觉紧凑

**导航变化**：
- 底部导航从 4 个 tab 减为 3 个：`记录 | 图鉴 | 档案 | 设置`（移除黑板 tab）
- 便利贴墙的展示放到档案页作为一个子 tab，或通过链接进入

**涉及文件**：
- `templates/index.html`：签到表单加模式切换 UI
- `static/css/style.css`：新增切换 tab 样式
- `static/js/main.js` 或 index.html 内的 script：切换逻辑 + 文字模式提交
- `templates/base.html`：底部导航移除黑板 tab
- `templates/board.html`：便利贴墙保留但不再通过底部 tab 直接进入

### 修改点 2：档案图鉴改造成植物图鉴（游戏化 Pokedex）

**背景**：用户希望把图鉴做成类似游戏的收集系统，已解锁/未解锁机制增强成就感。

**具体方案**：

**2a. 预设植物库**
- 预设 50 种常见室内/阳台植物
- 每个条目包含：名称、别名列表（用于匹配用户标签）、分类（观叶/多肉/花卉/蔬果）、灰色剪影图、手绘风格插图
- 分类示例：
  - 观叶类：绿萝、吊兰、龟背竹、琴叶榕、散尾葵...
  - 多肉类：玉露、石莲花、芦荟、仙人掌、虎皮兰...
  - 花卉类：月季、茉莉、栀子、长寿花、蝴蝶兰...
  - 蔬果类：番茄、辣椒、薄荷、罗勒、小葱...

**2b. 匹配机制**
- 用户标签通过别名表匹配植物库，命中任何一个别名就算解锁
- 植物库中没有的标签自动创建"自定义"条目，始终显示为已解锁
- 需要新增数据表存储用户的解锁状态

**2c. 图鉴首页（网格卡片）**
- 已解锁：显示手绘插图（默认）或用户自选封面 + 植物名 + 记录次数 + 养护天数
- 未解锁：显示灰色剪影轮廓 + 植物名称
- 卡片可按分类筛选（观叶/多肉/花卉/蔬果/全部）
- 显示收集进度："已解锁 12/50"

**2d. 图鉴详情页（点击某个植物进入）**
- 封面（大图，可更换为自己的照片）
- 养护数据：首次记录日期、记录总次数、养护天数、最近记录时间
- 成长时间线：该植物所有照片按时间排列（复用现有成长时间线）
- 前后对比滑动、GIF 合成、时间轴视频、生长日记（见修改点 3）
- 多株管理：同一种植物可有多株，支持分类和给每株单独命名
- 园艺计划：该植物的待办事项（见修改点 4）

**2e. 图鉴成为独立底部 tab**
- 底部导航：`记录 | 图鉴 | 档案 | 设置`
- 成长功能从档案页移到图鉴详情页内（用户打开图鉴 → 点植物 → 看成长轨迹）
- 档案页减为 3 个子 tab：记录列表 | 日历 | 标签筛选

**涉及文件**：
- 新增 `plant_library.py` 或在 `database.py` 中添加：植物库数据、解锁状态表、多株管理表
- 新增 `templates/codex.html`：图鉴页面
- 新增 `templates/codex_detail.html`：图鉴详情页
- `static/css/style.css`：图鉴卡片网格、剪影样式、解锁动画
- `static/js/main.js` 或新 JS 文件：图鉴交互逻辑
- `templates/base.html`：底部导航更新
- `app.py`：新增图鉴相关路由
- 素材：50 种植物的灰色剪影 + 手绘插图（可用 AI 生成，需保持风格统一）

### 修改点 3：成长功能增强——4 个新能力

**背景**：用户除了 GIF 合成，还想用更多方式回顾植物生长。

**具体方案**：

**3a. 前后对比滑动（Before/After Slider）**
- 选两张照片叠放，拖动滑块左右对比
- 纯前端 CSS/JS 实现，实现成本低
- 和 GIF 互补：GIF 看动态过程，滑动看静态细节

**3b. 时间轴视频（Time-lapse）**
- 选多张照片生成短视频（3-5 秒）
- 比 GIF 画质更高，可加背景音乐
- 需要后端处理（可用 ffmpeg 或前端 canvas 录制）
- 可分享

**3c. 生长数据可视化**
- 按月统计记录次数、照片数量的折线图/柱状图
- 让用户直观感受到"我这个月记录了 15 次，比上月多"
- 可用 Chart.js 或纯 CSS 实现

**3d. 生长日记**
- 以时间线叙事方式呈现照片 + 文字备注
- 像植物传记："3月买回 → 4月新叶 → 5月换盆 → 6月开花"
- 复用现有照片注释（caption），但以叙事时间线形式展示

**涉及文件**：
- 成长功能在修改点 2 中已移到图鉴详情页
- `static/js/main.js` 或新 JS：对比滑动组件、视频生成逻辑、图表渲染
- `static/css/style.css`：对比滑块样式、日记时间线样式
- 后端可能需要新增视频生成 API（如果用 ffmpeg）

### 修改点 4：轻量化提醒 + 园艺计划

**背景**：用户需要被温和提醒去关注植物，同时需要一个计划本来规划养护和心愿。

**具体方案**：

**4a. 轻量化提醒**
- 基于记录间隔计算"距上次记录 X 天"
- 图鉴卡片上显示："绿萝已 7 天未记录"
- 首页状态条显示提醒角标
- 可设阈值，超过 N 天未记录时标记变红
- 数据已有（签到的 created_at），只需前端计算 + 展示

**4b. 园艺计划（待办 + 计划迎接）**
- 图鉴详情页内添加计划列表
- 两类计划：
  - **待办**：养护任务（换盆/施肥/浇水等），关联具体植物 + 内容 + 截止日期
  - **计划迎接**：想入手的新植物，关联植物库条目 + 期望日期
- 支持创建/完成/删除
- 首页状态条显示待办数量角标，点击跳转
- "计划迎接"完成时（真的买了拍照记录），自动解锁图鉴条目

**数据结构**：
```sql
CREATE TABLE plans (
    id INTEGER PRIMARY KEY,
    type TEXT,           -- 'todo' 或 'wishlist'
    plant_id INTEGER,    -- 关联植物（植物库ID或自定义）
    content TEXT,        -- 计划内容
    due_date TEXT,       -- 截止日期（可选）
    completed INTEGER DEFAULT 0,
    completed_at TEXT,
    created_at TEXT
);
```

**涉及文件**：
- `database.py`：新增 plans 表
- `app.py`：新增计划 CRUD 路由
- 图鉴详情页模板：计划列表 UI
- `static/css/style.css`：计划卡片样式
- 首页状态条：提醒角标

## 四、关键设计决策记录

1. **影像签到 60% + 文字记录 40%**：文字记录合并到签到表单内，不单独占首页空间
2. **图鉴独立为底部 tab**：游戏化功能需要高可见度，不能藏在档案页子 tab 里
3. **成长功能归属图鉴**：成长是"围绕单株植物展开"，和图鉴是父子关系，不属于档案
4. **未解锁机制需要预设植物库**：没有预设库就没有未解锁概念，图鉴就退化成照片分类页
5. **匹配用别名表**：用户标签通过别名匹配植物库，同时保留自由输入（自定义条目）
6. **园艺计划放在图鉴详情页**：待办和植物强关联，首页只显示角标不占空间
7. **提醒基于记录间隔**：不做成"该浇水了"的管家式提醒，而是"X天未记录"的日记式提醒
8. **不做独立用户主页**：产品是个人日记而非社交平台，个人档案放在设置页入口即可
9. **成就系统分两层**：整体等级（首页状态条）+ 单株培育等级（图鉴详情页），不混在一起
10. **文案风格：不搞笑但要有趣**：温暖俏皮的手绘植物志人格，体现在空状态/提示语/成就解锁等辅助文案中

## 五、竞品调研结论

### 我们独有的优势（竞品都没有）
- GIF 动图合成
- XP/等级游戏化系统
- 手绘植物志视觉风格
- 前后对比滑动
- 黑板便利贴社交
- 植物图鉴收集系统（计划中）

- AI 植物识别（技术门槛高，需第三方 API）
- 病害诊断（同上）
- 多设备同步/云备份（当前是本地 SQLite）
- 光照检测仪（需要原生摄像头 API）

### 可能后续考虑的
- 养护共享（多人场景）
- 有毒植物警告（安全功能）
- 数据导出增强（已有基础版）

## 六、注意事项

1. **植物库素材**：50 种植物需要灰色剪影 + 手绘插图各一张，共 100 张图。建议用 AI 生成，需保持手绘风格统一。可以先做 20 种，后续逐步补充。
2. **别名表维护**：中文植物别名很多（如绿萝=黄金葛=魔鬼藤），需要仔细整理。
3. **修改点 1 和修改点 2 有先后依赖**：先做导航重构（移除黑板 tab，加入图鉴 tab），再做图鉴内容。
4. **现有成长时间线代码在 records.html 中**：修改点 2 需要将其迁移到图鉴详情页。
5. **黑板数据保留**：移除底部 tab 后，黑板页面和 API 都保留，只是入口变了（通过档案页链接或签到表单文字模式进入）。
6. **Flask 服务器**：开发时运行在 localhost:5000，启动命令在 plant-watering-v4 目录下 `python app.py`。
